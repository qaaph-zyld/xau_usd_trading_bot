## ⚠️ Status

This is an **educational / research project**, not an audited trading
system. The numbers in the [Backtest Results](#-backtest-results) section are
computed on **synthetic OHLCV data** generated by
[`scripts/generate_sample_data.py`](scripts/generate_sample_data.py) and have
**not** been validated on real historical XAU/USD data. They should be read as
"what the strategy does on a particular random walk", not as expected live
performance. Real-data validation, realistic-cost backtesting, and a
properly-wired risk module are tracked on the
[development roadmap](#-development-roadmap).

Do **not** trade real capital based on the numbers below.

| Feature | Description |
|---------|-------------|

| 📖 **Docs** | [Architecture](docs/ARCHITECTURE.md), [Prop firm guide](docs/PROP_FIRM_GUIDE.md). |

## 🏆 Prop Firm Challenge Mode

The repo includes an experimental "prop firm challenge" mode
([`scripts/prop_firm_system.py`](scripts/prop_firm_system.py),
[`src/strategy/final_prop_strategy.py`](src/strategy/final_prop_strategy.py))
that simulates a 30-day, 10%-target / 10%-max-drawdown challenge with an EMA +
MACD + RSI signal mix.

**This mode is currently exploratory.** Specifically:

- It is backtested on the synthetic GBM data shipped in `data/`, not on real
  XAU/USD history.
- Its parameters (`risk=8%`, `sl=0.8×ATR`, `tp=1.5×ATR`) come from a grid
  search on that synthetic data, which biases the result upward and is **not**
  a substitute for out-of-sample validation.
- It does **not** route position sizing through the `RiskManager` /
  `PositionSizer` classes in `src/risk_management/`; the size is computed
  inline as `(capital * risk) / (entry - stop)` with no spread, slippage, or
  commission applied.
- 8% per-trade risk is far above what a typical professional risk policy
  would allow. Six unlucky trades is enough to breach a typical 10% prop-firm
  drawdown rule.

In other words: do not interpret this mode's output as expected
performance, and do not use it to size real trades. Replacing the synthetic
data, wiring the risk module in, and capping per-trade risk are tracked on the
[development roadmap](#-development-roadmap).

```bash
# Inspect what the strategy currently does (synthetic-data backtest)
python scripts/prop_firm_system.py
```

| Win rate | 50.0% |

available in [`src/strategy/realistic_backtester.py`](src/strategy/realistic_backtester.py)

## 🛡️ Risk Management

### Position Sizing

```
Position Size = (Account Risk × Account Balance) / (Entry - Stop Loss)

Example:
- Account Balance: $100,000
- Risk per Trade: 2%
- Entry Price: $1,950
- Stop Loss: $1,930 (ATR-based)

Position Size = (0.02 × $100,000) / ($1,950 - $1,930)
             = $2,000 / $20
             = 100 units (0.1 lot)
```

### Risk Controls

- ✅ **Max Drawdown**: Stops trading at 15% drawdown
- ✅ **Daily Trade Limit**: Maximum 3 trades per day
- ✅ **Position Correlation**: Prevents correlated positions
- ✅ **Trailing Stops**: ATR-based dynamic stop losses
- ✅ **Risk/Reward Filter**: Minimum 2:1 ratio required
